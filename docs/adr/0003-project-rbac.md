# ADR-0003：采用组织、团队和项目三级 RBAC

- 状态：Accepted
- 日期：2026-07-17
- 范围：项目可见性、知识访问、文章操作和成员分配

## 背景

运营组为多个客户生产文章。员工可能分别负责不同客户项目，小组长需要掌握本组项目，组织管理员需要管理全部项目。让所有员工看到所有客户资料会扩大误操作和数据泄露范围；逐文件配置复杂权限则会显著增加管理成本。

## 决策

采用组织、团队和项目三级角色权限：

1. `org_admin` 可以访问和管理 Organization 内全部 Team、CustomerProject、知识库和交付记录。
2. `team_lead` 可以访问所属 Team 负责的全部 CustomerProject，并管理本组项目成员分配。
3. 普通成员不会因为加入 Team 自动看到该组所有客户资料。
4. `editor`、`reviewer` 和 `viewer` 只能访问 ProjectMembership 明确分配的 CustomerProject。
5. 前端根据权限隐藏或禁用操作，但后端 API、知识检索、对象下载和 Worker 任务必须独立执行授权检查。
6. 所有权限变更写入审计日志，包括授权人、目标用户、项目、角色和时间。
7. 项目交接通过修改 ProjectMembership 完成，不复制客户知识库。
8. 采用编辑自助交付：`editor` 可以完成其项目的人工检查确认、Word 导出和交付打包，不要求不同用户担任强制审批者。
9. `reviewer` 是可选质量支持角色，可以查看证据、版本和交付结果并提出修改，但不构成默认流程门槛。
10. `editor` 可以在被分配项目中确认自己或同项目成员上传资料的文件级分类并发布到知识库；删除已发布来源仍属于管理操作。

## 默认角色能力

| 角色 | 默认范围 | 默认能力 |
| --- | --- | --- |
| `org_admin` | 全组织 | 管理用户/团队/项目、查看和操作全部项目、审计 |
| `team_lead` | 本组项目 | 查看本组项目、分配成员、处理或复核文章 |
| `editor` | 被分配项目 | 上传资料、运行抓取、编辑知识候选、生成和编辑文章、确认人工检查、导出和打包 |
| `reviewer` | 被分配项目 | 查看证据、版本和交付结果，提出修改或协助复核 |
| `viewer` | 被分配项目 | 只读查看项目、文章和交付记录 |

删除知识来源、删除项目和成员管理仍属于管理操作，不因编辑自助交付而自动开放给 `editor`。

## 后果

正向影响：

- 员工界面只显示其负责客户项目。
- 组长可以在不获取组织管理员权限的情况下管理本组工作。
- 客户知识库不会因人员交接而复制或丢失。
- 服务端权限边界可以覆盖前端、API、检索、文件和后台任务。

成本与风险：

- 所有服务方法都需要携带 Actor 与 Project Scope。
- 批量任务必须验证操作者对每个目标项目的权限。
- 需要处理成员移除后正在运行的任务和短期下载链接。
- 自助交付降低流程阻塞，但需要完整版本记录和审计日志来追踪操作人。
