# ADR-0005：服务器准源与本地单机版边界

- 状态：Accepted
- 日期：2026-07-17
- 范围：生产数据权威性、本地单机版、离线能力和数据回传

## 背景

现有文章工作台可以在 Windows 本机独立运行，适合开发、演示以及服务器不可用时处理已有文件。多人共享版本上线后，如果本地版和服务器版都能修改正式项目并自动双向同步，就必须处理任务、正文、知识快照、图片、状态机和导出物的冲突合并。这个成本与当前业务规模不匹配，也会破坏项目审计链。

同时，完全删除本地版会降低开发调试便利性，并失去服务器故障时的紧急导出能力。

## Decision

1. 服务器端 PostgreSQL、对象存储和知识索引是生产数据的唯一准源。
2. 保留当前本地单机版，用于开发、演示和紧急导出。
3. 本地单机版默认使用测试数据，或使用从服务器显式导出的只读项目包。
4. 第一版不实现本地与服务器的自动双向同步、离线编辑队列或冲突合并。
5. 本地 SQLite、任务目录和知识目录不得被描述或操作为生产知识库的权威副本。
6. 服务器临时不可用时，本地版可以从已有项目包生成或重新导出文件，但不能自动推进服务器端任务状态。
7. 需要作为正式交付记录保留的本地结果，必须在服务器恢复后通过显式上传或导入操作回传，并记录操作者、来源、时间、文件哈希和目标项目。
8. 服务器与本地结果冲突时不自动覆盖；默认保留服务器版本，并把本地结果作为待确认的新版本导入。

## 允许和禁止的操作

| 场景 | 本地单机版 | 正式服务器 |
| --- | --- | --- |
| 开发和功能测试 | 允许 | 不建议使用生产项目测试 |
| 产品演示 | 允许使用脱敏或测试数据 | 允许使用受控演示项目 |
| 读取正式项目 | 仅限显式导出的只读项目包 | 允许，受 RBAC 控制 |
| 修改正式任务状态 | 禁止自动回写 | 允许 |
| 紧急生成 DOCX/交付包 | 允许 | 正常入口 |
| 回传本地结果 | 显式上传为待确认版本 | 审核后入库并写审计日志 |
| 自动双向同步 | 不实现 | 不实现 |

## Consequences

### 正面影响

- 避免双向同步和冲突解决的高复杂度。
- 保留本地开发、演示和应急能力。
- 正式项目始终有明确的数据准源和审计链。
- 后续若确有离线编辑需求，可以基于实际冲突类型单独设计。

### 代价

- 本地版不能被当作完整的离线生产客户端。
- 紧急导出的结果需要人工回传并确认。
- 需要定义只读项目包和本地结果导入包的格式。

## 后续实现约束

- 项目包必须包含 `organization_id`、`project_id`、任务版本、导出时间和内容哈希。
- 本地界面必须明显显示“本地单机模式”，避免操作者误以为正在修改服务器项目。
- 导入本地结果时必须创建新版本，不能直接覆盖服务器正文或交付包。
- 若未来考虑双向同步，必须建立新的 ADR，并先证明离线编辑是高频刚需。
