# ADR-0014：按句子计算知识库支撑率

- 状态：Accepted
- 日期：2026-08-21
- 范围：知识库支撑率、EvidenceLink、硬事实校验与文章复检
- 取代：ADR-0006

## 背景

按段落统计时，只要段落中一个观点有证据，整段都会计为已支撑，容易让长段落的比例虚高。运营人员需要看到当前正文中有多少实质性句子真正使用了项目知识，同时仍要把硬事实证据门禁单独保留。

## Decision

1. 主指标名称为“知识库支撑率”，不称为文本重复率或公开引用率。
2. 计算公式为：`有有效证据的合格正文句数 / 全部合格正文句数`。
3. 引言、普通正文、列表项、FAQ 回答和表格事实项进入句子切分；标题、FAQ 问题标签、图片与 `img` 索引块、URL、代码块、空内容及少于 5 个可见英文词的片段不进入分母。
4. 普通知识支撑必须建立句子级 EvidenceLink。向量或关键词相似度只能召回候选，不能单独判定支撑关系。
5. EvidenceLink 必须指向当前项目中已发布、未失效且非 `official_blog` 的 KnowledgeChunk，并能支撑该句的主要观点。
6. 句子包含多个独立事实时，只有全部关键事实均有依据才计为完整支撑；否则应拆句或计为未支撑。
7. 产品参数、认证、尺寸、材料、产能、交期等硬事实仍单独统计，必须由 `hard_fact` 来源支撑，目标覆盖率为 100%。
8. 每个句子保存稳定 `sentence_id` 与 `sentence_hash`。正文修改后，仅哈希变化的句子失效；未变化句子的有效绑定可以继续使用。
9. 官网博客只作为正文写作参考，不进入 Evidence Pack、知识库支撑率或硬事实覆盖率。
10. 检查失败不得阻断正文保存或文章生成；UI 显示未完成或已失效状态，并允许人工重新检查。

## UI

复检页在 AI-rate 卡片下方显示一个紧凑的“知识库支撑率”摘要卡：

- 主数字显示百分比和 `已支撑句数 / 合格句数`。
- 硬事实存在缺口时显示醒目告警；全部满足时显示通过状态。
- 正文修改后显示结果失效，并提供“重新检查知识库支撑率”操作。
- 逐句映射使用独立详情页，避免在复检侧栏同时堆叠正文、证据和控制项。
- 详情页保留正文段落顺序；已有支撑的句子使用绿色背景，并同时显示可聚焦的引用编号，不能只靠颜色表达状态。
- 每个引用编号链接到本页证据卡；公开来源提供官网超链接，内部资料提供项目知识证据预览链接。
- 详情页不得输出 Evidence Pack、检索查询或模型推理过程，只显示已持久化的有效 EvidenceLink 和必要证据摘录。

## Consequences

- 指标比段落统计更接近真实知识使用情况。
- 句子切分和证据判断成本高于段落统计，需要稳定规范化算法和一次保守的证据相关性审核。
- 文章改写、人化或 SEO 修改后必须根据句子哈希重新计算；链接恢复和图片索引变化不应使可见句子绑定失效。
